## Вопрос: почему ChangeName изменяет объект, видимый снаружи, а ReplaceHero не заменяет исходную переменную?

При передаче объекта класса по значению копируется ссылка на объект в памяти, а не сам объект

- ChangeName через эту копию ссылки обращается к оригинальному объекту и меняет его имя. Поэтому изменения снаружи видны.

- ReplaceHero создает новый объект (new Hero()) и присваивает его локальной копии ссылки. Исходная переменная снаружи по-прежнему указывает на старый объект в памяти, поэтому она не заменяется.

## Вопрос: почему следующий код не компилируется?

Потому что in передает параметр по ссылке, но только для чтения. Компилятор строго запрещает изменять значение параметра, объявленного с in, чтобы гарантировать безопасность данных внутри методов.

## Шаг 2. ref — Swap

При обычной передаче метод получает копии значений. Метод Swap поменяет метами только свои локальные копии, а оригинальные переменные в вызывающем коде останутся прежними. Чтобы метод мог изменить сами исходные переменные, ему нужно передать ссылку на них в памяти - для этого и нужен ref. Без ref у метода просто нет доступа к оригиналам.

# ПР7. Ответы на контрольные вопросы
1. Что именно копируется при передаче параметра по значению? Объясните разницу для int и для объекта класса. 

Копируется сам аргумент. Для int - копируется число, поэтому изменение копии внутри метода не меняет исходную переменную. Для объекта класса значение - это ссылка на объект: копируется ссылка, поэтому через нее можно изменить поля объекта, но переприсвоение заменит только локальную копию ссылки.

2. В чём разница между ref и out с точки зрения обязательной инициализации переменной до и после вызова метода? 

ref: переменная обязана быть инициализирована до вызова, метод не обязан ей присваивать

out: инициализация до вызова не нужна, метод обязан записать значение на всех путях выполнения.

3. Почему у int.TryParse используется именно out, а не ref, для параметра, куда записывается результат? 

Методу не важно, что было в переменной раньше - он сам обязан записать туда результат. out не требует инициализации до вызова и гарантирует запись, что точно отражает "здесь будет результат". ref требовал бы готового значения и не гарантировал бы запись.

4. Какую проблему решает in? Почему он интереснее для больших структур, чем для int? 

in передает параметр по readonly-ссылке: метод получает ссылку, но не может изменить значение. Проблема: при обычной передаче по значению структура копируется целиком. Для больших struct экономит копирование всех полей, а для int выигрыша почти нет. 

5. В каком порядке относительно обязательных параметров должны располагаться необязательные параметры? 

Необязательные - после всех обязательных. Если поставить необязательный перед обязательным, то будет ошибка компиляции.

6. В чём преимущество именованных аргументов при вызове метода с несколькими необязательными параметрами?

Позволяют пропускать необязательные параметры, менять порядок и явно видеть, что чему соответствует.
